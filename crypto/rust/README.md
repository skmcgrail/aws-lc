# Rust in libcrypto

Experimental, opt-in Rust components of libcrypto. They are built and linked
only when AWS-LC is configured with `-DENABLE_RUST=ON`.

## Layout

| Path | Purpose |
| --- | --- |
| `caracal/` | Native Rust implementations. Safe Rust, no C types. |
| `caracal-ffi/` | C ABI over `caracal`, built as a `staticlib` and linked into libcrypto. |
| `caracal-ffi/include/caracal_ffi.h` | C declarations for `caracal-ffi`, generated by cbindgen. Do not edit. |
| `rust.c`, `internal.h` | libcrypto's C side: wraps `caracal-ffi` calls and maps errors to the error queue. |
| `rust_test.cc` | `crypto_test` cases that call Rust through libcrypto. |

Code in `crypto/fipsmodule` must not call into Rust: `AWSLC_RUST` is only
defined for the non-FIPS libcrypto objects.

## Building

```sh
cmake -GNinja -B build -DENABLE_RUST=ON
ninja -C build crypto_test
./build/crypto/crypto_test --gtest_filter='RustTest.*'
```

CMake runs `cargo build --locked` on every build (Cargo tracks its own
dependencies), using the `dev` profile for `Debug` and `release` otherwise.
Output goes to `<build dir>/cargo`. When cross-compiling, set
`-DRUST_TARGET=<triple>`.

The Rust crates can also be developed directly:

```sh
cd crypto/rust
cargo test
cargo clippy --all-targets
cargo fmt --check
```

The minimum supported Rust version is set by `rust-version` in `Cargo.toml`.

## C header

`caracal-ffi/include/caracal_ffi.h` is generated by
[cbindgen](https://github.com/mozilla/cbindgen) and committed, so builds do
not need cbindgen. After changing anything exported from `caracal-ffi`, run
`util/generate_caracal_ffi_header.sh` and commit the result. The script pins
the cbindgen version, since its output can change between releases, and prints
the install command if cbindgen is missing or the wrong version.

CI runs `util/generate_caracal_ffi_header.sh --check` and fails if the
committed header is stale. Doc comments on exported items are copied into the
header verbatim, so write them for C readers. Configuration is in
`caracal-ffi/cbindgen.toml`.

## Conventions

- Everything is `no_std`, so libcrypto does not pull in the Rust standard
  library, its allocator, or system libraries. Panics abort.
- Exported functions follow libcrypto conventions: return 1 on success and 0
  on failure, accept NULL with a zero length for empty buffers, and never
  unwind. Every `unsafe` block needs a `// SAFETY:` comment (enforced by
  clippy).
- Rust symbols are internal to libcrypto. In ELF shared builds they are
  hidden with `--exclude-libs`. In static builds the archive is installed next
  to `libcrypto.a` and added to the CMake package and pkg-config file.

## Not yet supported

`ENABLE_RUST` is rejected with `FIPS`, `BORINGSSL_PREFIX`, and symbol
versioning (`ENABLE_SYMBOL_VERSIONING`, on by default with `ENABLE_DIST_PKG`).
